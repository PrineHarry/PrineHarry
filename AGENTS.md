# Repository homepage maintenance

These local documentation rules apply to this public repository only.

- Preserve existing source, attribution, license terms, verified project information, and repository-specific rules. Never expose private data, credentials, unrelated private project names or internal links.
- On each change, assess whether the README needs an update. If it does, update the affected summary, status, links and navigation in the same reviewed change; otherwise document why no homepage change is needed.
- Keep the layout flexible. Use concise headings, accessible visual assets, valid local paths, and accurate status statements. For longer documents, use a hierarchical table of contents, stable anchors, and return links as appropriate; short pages need no extra structure.
- Preserve important verified documentation, explicit priority labels and approved constraints. Do not invent ratings, claim unverified features, or change source licensing.
- Review relative links, headings, image accessibility and rendering before approving homepage changes. Record checks actually run and outstanding issues. Do not introduce automated workflows or change branch protection without separate authorization.
- Use independent review branches and pull requests. Do not merge or publish changes without the owner's explicit approval. This policy does not modify application code, deployment configuration or existing README content.
- Browser reading enhancements are optional local tools. The public README must remain usable without an extension; no extra site permission, data collection or installation is required.

Preserve the profile's current identity, existing links, assets and contribution animation; do not modify the workflow or add unverified personal claims.
